# G06-06C3-S2d — UI rollout binding decisions

2026-10-30. S2c accepted. Implement ONE bounded slice on director_window.py + pages/review_page.py, using existing StylePage, DirectorConfig and backend APIs. No new architecture/design round or provider work.

1. Gate0 is actual StylePage draft, not old saved config. _sync_all_pages_to_config returns success bool and respects StylePage.save_to_config False. _get_current_director_context supplier must validate/commit current in-memory StylePage draft before reading config.get_creative_context, or return unavailable context. All source prompt actions must use current producer; invalid draft/supplier failure cannot fallback to old config/stored context or mutate generation/cancel/dispatch. _on_run_ai_script must honor failed sync. Do not refactor unrelated source scan/build pipelines or write project settings to disk.
2. _sanitize_and_validate_context accepts/normalizes/owns creative_context, rejecting malformed supplied values; absent/None/canonical empty retain legacy. _extract_context_signature keeps existing full16field domain/order; for nonempty creative add a separately tagged digest component rather than replacing the full signature with creative digest. Legacy empty preserves old signature representation. Snapshot ui_context_signature, artifact.context_signature and evidence signatures keep original meaning; creative proof separately captured in pending.
3. For all6source prompt intents, request carries owned canonical creative_context, pending has independent expected creative digest (including explicit None for legacy). Preflight and terminal revalidate current producer context; nonempty digest must exactly match current input, pending and backend result/snapshot/artifact as applicable. No missing-proof fallback, result used as expected, or raw request pointer trust. Legitimate manifest metadata update may update full signature after publication but cannot launder changed creative input. Pending generation/request/intent/exact worker ownership rules stay.
4. Reuse existing supplier/physical-worker registries and StylePage.config_changed signal; no polling timer/parallel job bus. Creative edits immediately mark prepared prompts/batches/overview stale and prevent copy/intake/direct AI dispatch. Pure getters also enforce freshness, including programmatic config change. Invalid draft should not be 'fixed' by saving defaults/reloading UI. Keep prior user JSON/batch drafts for reference; no clearing whole historical ledger or altering cuts to satisfy brief. Logical invalidation must not release physical-worker ownership/busy controls early.
5. Preserve each old intent guard. copy_batch/intake require normalized snapshot, matching creative digest and full UI proof; intake allowed modes/raw payload SHA/replacement races unchanged. overview uses same captured creative snapshot, ledger/source/exact artifact validator; no context duplication conflicts. All known source intents now supported; do not disable batch/draft/overview whenever default style produces nonempty context. Kinetic remains separate, no creative payload passed to its worker/formatter or fake visual/style interpretation.
6. Manual copy/direct local/cloud share prepared source prompt; controller.run_ai_script only once after exact pending ID+current prompt+creative proof. This slice does not implement or prove providers. No new prompt rewriting/execution/approval schema.
7. Valid existing None/empty standalone ReviewPage fixtures remain supported. Tests that manually create pending records must model explicit expected legacy None and real authority instead of bypassing new proof guards. Don't weaken proof checks to preserve forged tests. No backend changes to make UI tests pass.
