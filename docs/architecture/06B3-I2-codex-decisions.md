## Policy / source corrections
1. Chọn **strict opt-in read**, không chỉ precheck `online/root.is_dir`. Online registry corrupt vẫn online=true/root là directory; `assets()` nuốt ValueError tại outer except. `read_json` còn trả default khi file thiếu. Precheck không khôi phục error evidence đó. StorageManager thuộc G02/G04, không phải pure06B1. Có quyền sửa hẹp assets() trong slice này với default compatibility.
2. Thêm keyword-only `StorageManager.assets(*, raise_on_error: bool=False)`. Flag phải strict bool; sai kiểu ->ValueError trước IO. False giữ hành vi/callers hiện hành. True strict read: không biến missing required metadata, IO error, corrupt/oversized JSON hoặc malformed registry/snapshot thành []/default. Valid empty catalog vẫn[]. Đây là matching advisory metadata read, không write guard/migration/recovery và không quyền execution.
3. Strict ONLINE/READ_ONLY/FULL đọc được: đọc registry bắt buộc và validate envelope packs/assets lists. Strict OFFLINE có cấu hình hợp lệ: đọc snapshot bắt buộc, origin_library_id khớp cấu hình, registry shape hợp lệ, rồi trả records offline theo policy hiện hữu. Chưa cấu hình/offline không có snapshot hoặc không xác minh được origin ->StorageOfflineError; ERROR ->error, không catalog empty. Không blanket-deny offline vì phải hỗ trợ offline recommendations. Dùng existing state/identity mechanisms, không sửa get_state/require_online/registry semantics rộng.
4. Strict reader riêng tư chỉ khi cần: bounded metadata read<=MAX_JSON, không read_json default cho required files, không swallow is_file missing/permission; byte gate trước/sau read. Không tự tạo directory/snapshot, fallback repo hoặc ghi file. Giữ resolve companion/source inference và runtime fields hiện hữu; không refactor storage. Error loại OSError/ValueError/StorageOfflineError phải ra caller, không claim atomic filesystem snapshot giữa các đọc hoặc phát hiện mọi hot-unplug race.
5. Worker phải phát đúng **một logical terminal kể cả cancel**; prototype return không signal khi cancel là sai. Một worker active không đồng nghĩa exactly-once terminal. QThread.finished là physical completion riêng, không override bằng signal custom. Không delete thread còn chạy, không terminate, không event loop GUI wait để ép xong. UI registry/close pending chưa thay đổi ởP1, không claim UI lifecycle đã kiểm chứng.
6. I2-P1 là worker + strict provider prerequisite, **chưa headless Review integration**. Tests không thể chứng minh GUI stale-result rejection khi không sửa ReviewPage. UI P2 sẽ validate worker identity/generation/pending plan và storage context, không chỉ compare saved string với chính nó.

## API worker chốt
Một module mới `src/ui/director/workers/asset_matching_worker.py`:
- Frozen `AssetMatchingOutcome`: status:str ('completed'|'error'|'cancelled'), generation:int, plan_revision:str, sidecar:Optional[AssetMatchingSidecar]=None, error_message:str=''. status completed iff valid sidecar; error/cancel không publish sidecar; error có message Việt, không trace/proxy/widget trong payload.
- `AssetMatchingWorker(batch:AssetDemandBatch, generation:int, *, storage_factory=None, parent=None)`. Không separate plan_revision có thể mâu thuẫn; derive từ validated owned batch. generation strict nonnegative int, no bool. storage_factory None hoặc callable không args; constructor **không IO/call factory**. Default factory tạo fresh StorageManager trong run, không giữ manager từ GUI. Batch validate constructor và trước run; no raw plan/widget refs.
- Signal duy nhất `terminal = Signal(object)` cho outcome. Native QThread.finished giữ nguyên. `cancel()` idempotent, lưu cancel request bền ngay cả trước start (requestInterruption trước start riêng lẻ không đủ), không IO. Cooperative checks trước factory/provider, sau matching, trước assembly/terminal. Nếu cancel đã yêu cầu khi exception/complete chuẩn bị phát, cancelled thắng; không chạy lại/provider retry.
- run nonempty requests: storage_factory đúng1call trên worker, provider `storage.assets(raise_on_error=True)` đúng1call qua OfflineAssetMatchingService. Nối thật service và PlanDemandAdapter.assemble, không duplicate matching loop hoặc đổi06B2 để có cancellation trong từng request. Noninterruptible load/match được ghi rõ; cancel chờ checkpoint rồi discard result.
- requests rỗng: không storage_factory/provider, assemble empty/noneligible batch và completed sidecar với counters trung thực; không báo '0 nhu cầu' nếu vẫn có invalid/unsupported/overflow. Cancel sớm ->cancelled,0factory. Mọi controlled fault trong lifecycle ->exactly1error outcome, process/thread kết thúc sạch. Generation/revision echo chính xác, không là GUI authority proof.
