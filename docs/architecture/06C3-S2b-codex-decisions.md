# G06-06C3-S2b — Binding rollout decisions

2026-10-30. S2a accepted with recorded limits; design reviewed and APPROVED_WITH_BINDING_CORRECTIONS for one backend batch slice. No new design round is required before implementation.

1. Preserve existing identity domains. PreparedBatchSnapshot.ui_context_signature is the full ReviewPage configuration signature, not a CreativeContext digest. ReviewPage assigns it via dataclasses.replace around line 4122 after normalization. compute_snapshot_id currently does not hash this UI field. Do NOT redefine/hash/reuse it for creative metadata: existing UI replacement would invalidate every snapshot. evidence_context_signature and its context_signature alias also keep their original meaning.
2. Add a distinct optional creative_context_signature to PreparedBatchSnapshot at the END, strict canonical lowercase 64-hex SHA256 when present. Include it in to_dict only when present to preserve legacy serialized keys; preserve it during normalization and bind it into compute_snapshot_id with an explicit separate canonical domain only when non-None. Extend that function compatibly with an optional keyword-only argument. Legacy missing/None keeps exact old snapshot IDs and prompt bytes. No new external trust or authentic-signature claim; this is app-owned consistency binding.
3. Only prepare_batches/copy_batch are added to the nonempty supported set in this slice, alongside copy_video/run_ai. Gate both request and run boundaries. The separate signature comes from the constructor-owned normalized context; never trust caller-supplied digest or a missing-value fallback. copy_batch must compare captured context to snapshot before source/cache IO. A creative snapshot cannot be replayed with absent/empty context, and a nonempty request cannot replay a legacy snapshot. Deny stale/malformed/mismatched input with one controlled invalid_snapshot and zero prompt publication. All six existing expected bindings, UI checks, source freshness, exact digest/byte/index guards remain mandatory.
4. Full creative JSON belongs in the actual batch wrapper before partitioning and is counted by existing BatchBudgetConfig. Keep request cap 1..32768; do not raise cap, trim requirements or use a post-render appended block. Source-only wrapper must not scan the library. No rewriting A1/A2, geometry, source cache or matching. Absent/empty context remains byte-identical, including old IDs.
5. Existing early-return success branches prepare_batches and copy_batch must each carry the correct additive creative_context_signature for nonempty context, with snapshot signature matching. Neither currently reaches the direct formatter's final signature injection. Copy is exact frozen prompt replay, no new formatting or analysis.
6. Global UI rollout is still deferred: backend batch support alone does NOT solve validate_batch_draft/copy_project_overview nonempty gates. Those remain explicit unsupported in this slice and must be addressed by a bounded follow-up policy/implementation before global UI producer wiring. V2 Kinetic remains separate; do not smuggle creative fields into enums or pretend analyzed references. D01/D02/D03 unchanged.
7. Correct design documentation now: save_to_config is around style_page.py:1377, not 91; use actual STYLE_VLOG/style-preset constants instead of asserting the stored default literal is travel_vlog; label S2b UI support as PROPOSED, not already fully supported. Empty canonical JSON contains default keys, not just style_preset. Correct signature domains, actual existing hash behavior and the remaining draft/overview blockers. No claim entire rollout is safe or ready from this slice alone.

Evidence remains offscreen/backend. Provider networking, local/reference inference, desktop tests and G07 execution are out of scope.
